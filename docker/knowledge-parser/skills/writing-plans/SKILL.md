# Writing Plans

Before changing files, make a concise internal plan based on the user's requested output and the complete source document.

1. Identify the document's purpose, audience, main claims, constraints, causal relationships, examples, and reusable guidance.
2. Decide whether one coherent document is sufficient. Create child documents only for themes that can stand alone and are useful independently.
3. Map every important source section to the planned output so information is not silently dropped.
4. Preserve uncertainty and provenance. Never invent dates, facts, or conclusions.
5. Review the planned structure for repetition and fragmentation before writing.

The user's instructions override output-location conventions. If the user says not to create a plan file, keep the plan internal and write only the requested deliverables.
