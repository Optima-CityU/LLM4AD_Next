# Proposal foundation and document structure

Use this method to establish or refine the research foundation, document
organization or presentation requirements needed for the author's request.
Read [the foundation and coordination guide](../proposal-foundation-layout/references/foundation-and-coordination.md).

Inspect the nine root chapters and state/log for a new proposal, or the existing
Markdown/Typst sources exposed by workflow context. Follow
[the author-paced workflow](author-paced-workflow.md) for filenames, Phase 0–6
and recovery. Preserve confirmed scope, evidence, requirements, decisions,
uncertainties and author facts in the sources and durable author context. Use
descriptive stable headings or existing context keys rather than a fixed intake
form. Do not migrate legacy projects automatically.

Ask only about missing or conflicting choices that materially change scope,
compliance or document architecture. Do not invent grant rules, institutional
facts, page/word limits or required metadata. Reuse an existing official outline
or author template when supplied; distinguish current verified requirements
from dated examples.

Author new content in the canonical Markdown chapters; preserve the format of
legacy edits. Keep mathematical meaning, labels, citation identities, figure
references and bibliography consistent. The main agent can integrate changes
across relevant passages within the requested scope; research methods do not
own particular files.

Presentation and Typst/PDF conversion belong to the platform only after the
author's explicit **确认并排版** UI action. The model does not generate or export
Typst/PDF automatically. Normal authoring requires no compiler, shell commands or
formatter checks. For export-template provenance only, see
[the retained adaptation note](../proposal-foundation-layout/references/typst-template.md).
A failed PDF export does not discard the saved Markdown draft.
