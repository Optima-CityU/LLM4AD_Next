# Design

The canonical package is `llm4ad.gateway`: `sdk/` contains the existing SSE, HTTP, worker, journal and recovery implementation. `templates/custom/` holds reusable launcher templates independently of complete `examples/`. Each example co-locates source and deployment. HGamey separates `compilation/` (GLSL/SPIR-V/native layer), `execution/` (persistent queue, API, lease, device lifecycle, ADB and storage), `protocol/` (game A/B and pinned telemetry), configuration and optional runtime/evidence hooks. Its JSON configurations are named `settings.json`, `game-ab.json` and `game-check.json` within the example. The generic root service only handles process signals. Existing remote modules are aliases, so classes, monkeypatch points and worker identities do not fork.

Direct `start --adapter example|hgamey` uses installed code and requires no export or generated project. `--evaluator FILE.py:Class` and `package.module:Class` retain user ownership of compilation, execution, scheduling, local locks and aggregation. `source` reports installed paths without side effects. `check` invokes the actual isolated worker without registering a platform gateway. HGamey is loaded only when selected, builds its native runtime from included source or uses locally prepared tools, and retains device locking, startup baseline checks, cancellation/recovery and acknowledged evidence cleanup.

Optional `init` copies the actual installed example plus Docker templates into an editable directory; conflicts are checked before writing. Generated system/container launchers call the same core SDK. Users can provide their own launch implementation. No template engine path is required for direct execution. Explicit flags override a JSON environment mapping, then environment variables. The effective runtime environment reaches constructors and spawned children and is restored when the CLI exits.

The HGamey executor and exact-layer builder were ported from the supplied, device-validated extraction; upstream protocol files retain their provenance and bytes. Native artifacts, Android tools, NDK, pairing keys, references and runtime state are not bundled as generic dependencies. Example-path Python compatibility entries delegate to the installed implementation rather than maintaining parallel implementations.

Verification covers direct wheel startup/local execution outside the checkout, optional template generation, source visibility, Docker configuration, legacy SDK imports and exported runtimes, and the packaged HGamey lifecycle using isolated fake-device fixtures. No phone or deployed service is restarted by this change.

The HGamey case now includes the scoped native source from the device-validated extraction under `native/vendor/hgamey`: phonefarm, Vulkan layer, device runner, refbench and original contracts. Original optional orchestration/dashboard services and generated/captured data are excluded; literal Rust build inputs are retained. Its own Dockerfile builds native tools and prepares NDK/ADB/telemetry before installing the SDK. A source manifest records imported scope and hashes. Phone Root, pairing, official game installation and test APK installation are documented in README rather than a new provisioning workflow.


The shared `sdk/service.py` now owns all evaluator startup, ownership leases, readiness sequencing, signal-driven draining, cleanup scheduling and health aggregation. `sdk/health.py` serves the same loopback contract and state-directory-discovered probe for every entrypoint and Docker template. Connection observations belong to `Gateway`, without a case-specific subclass. `sdk/retention.py` owns acknowledgement fences, receipts and file pruning; optional policies contribute only externally validated targets and recovery obligations. The HGamey evaluator supplies a `create_runtime(environment, evaluator)` hook; the CLI has no HGamey startup branch. HGamey retains `runtime.py` for device/executor/profile readiness and `evidence.py` for device ownership/restoration, with the old standalone service/health/retention modules removed. Normal custom evaluators implement only their evaluation interface.

The reporting audit adds durable attempt-scoped journal observations and ordered messages using additive tables. `Reporter.message`, `metadata`, `progress` and described artifacts share the fenced outbox; messages do not change timing. Result normalization and exception diagnostics live in `sdk/reporting.py`, including worker initialization failures and subprocess output. `EvaluationError` carries optional domain metadata, feedback and evidence; `EvaluationUnavailableError` preserves recovery uncertainty. Existing `EvaluationResult.metadata` contains `evaluation_messages` and `artifact_descriptions`, so no model or generated frontend schema changes are required. Final failed/cancelled results use the same object-storage path as success, with concise terminal errors in the database and full data in RustFS. Files upload before final acknowledgement; live file previews remain outside this change. The platform SDK client validates rich failed results instead of rebuilding a minimal result.

The task lifecycle is also a common SDK responsibility. `sdk/lifecycle.py` supplies attempt-scoped OS-released SQLite execution leases and durable worker controls, independent of adapter-owned external saved handles. A surviving local worker keeps its lease across gateway loss and observes persisted stop requests in a small watchdog thread; the new gateway does not infer ownership from reusable PIDs. Once a local worker has stopped, an unfinished managed execution with no external handle may replay through the inherited recovery implementation. The SDK cleans its unuploaded partial outputs, restarts the execution clock, preserves messages, and applies the same concurrency limit to fresh/recovered jobs. Accepted work that never started resumes its normal download/start path. Intentional suspension, missing journals, unknown legacy execution and durable cancellation do not trigger blind replay.

Ordinary adapters implement only their contract and evaluation function. Optional `before_task(job, reporter, operation)` / `after_task(job, reporter, operation, result=..., error=...)` surround SDK-selected evaluate, recover and cancel operations; hook errors retain the original domain failure. The SDK owns termination and confirmation transitions, including cancellation of a surviving local worker; HGamey's existing external recover/cancel semantics remain untouched. Forced worker termination cannot run arbitrary worker-local finally blocks, so platform cancellation hooks run in the gateway around local termination and external confirmation. Shared retention defers cleanup while any execution lease remains held and removes the released lease files after result/file acknowledgement. No new framework, dependency or platform API is required.

Joblib was evaluated as an execution backend. The installed 1.5.3 implementation and a two-worker experiment confirmed that cancelling an already-running future returns false, while executor shutdown with kill_workers aborts both tasks. Therefore the SDK retains bounded per-job process isolation for independent cancellation and persisted recovery. Joblib remains optional within a domain evaluator for independent instance-level numerical work; a reusable in-memory pool is not the durable gateway queue and adds no recovery semantics by itself.

A spawned process-tree guardian holds an independent lease until forced tree termination is signalled, preventing a dead worker leader from being mistaken for completed cleanup. POSIX guardians share the isolated worker's group, ignore graceful termination and kill that group on a durable stop request or root death, including descendants ignoring SIGTERM. Windows uses taskkill for a live root; an unconfirmed tree after unexpected root death remains unknown and is not automatically replayed. Cancellation and deadlines reread external handles after local termination. Pending spawns are recorded before child startup, adopted external workers retain a recovery trigger, and explicit CLI resolution holds the execution lease plus an atomic state/attempt check to preserve terminal results.
